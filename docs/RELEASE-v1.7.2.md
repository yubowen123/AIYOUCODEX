# AIYOUcodex v1.7.2

修复 Dot 入口消失、点击无响应、一直加载，以及启动配置超时后错误显示“此账户无法使用消息功能”的问题。继承 v1.7.1 的已有功能和主题。

## 具体原因

宿主启动时，官方登录后功能配置请求超时，转入备用 SDK。备用 SDK 使用客户端构造的身份，缺少服务端补全的配置属性，因而将 Dot 判为关闭。普通配置刷新沿用备用身份，不能恢复完整官方配置。

本次实机诊断确认：账号、用户、客户端版本和品牌一致时，重新请求官方登录配置返回 Dot 已开放。因此，此次提示不能解释为账号本身无权使用 Dot。

## 修复行为

- 选择当前可见的产品页头，模式切换后保留 Dot / Claude 双入口；原生入口暂不可见时，Claude 仍可独立打开。
- 使用产品层原生导航，优先打开当前账号已有的主 Dot，并传递原生预加载状态；导航等待有上限、重复点击合并。
- 启动后等待 SDK 就绪，检测到原生配置请求失败时尝试恢复；点击 Dot 前也可以触发受限频率的恢复。
- 仅使用官方返回的完整配置和身份，校验账号、用户、客户端实例、版本及品牌。官方返回关闭时仍保持关闭，不固定开启开关。
- 不同账号的缓存主角色不会覆盖当前账号的选择；旧版原生入口转发保留。
- 不发送测试消息、不重放任务、不修改原生应用安装包。正常功能配置刷新保留。

## 验证范围

本机用户于 2026-10-17 确认 Dot 已正常打开，可看到消息输入框。原生消息入口判定已恢复为可用。真实消息发送尚未验证，Windows 桌面行为尚未实机验证。

隔离浏览器和恢复逻辑回归覆盖：官方配置恢复、官方关闭保留、身份变化拒绝、请求失败、延迟启动、重复点击、正确导航、隐藏旧页头、其他账号缓存隔离，以及 Claude / 未发送草稿保留。

兼容性依据为宿主 26.1007.71326（build 20398）。其他宿主版本在无法识别原生接口时保留原生路径与失败提示，不承诺所有版本均支持自动恢复。验证期间观察到宿主页面重新加载，不能将过程描述为完全无页面重载。GitHub 双平台检查结果以本版 PR Checks 为准。
