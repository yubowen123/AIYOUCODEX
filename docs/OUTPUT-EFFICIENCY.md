# 输出与上下文管理

AIYOUCODEX 的输出与上下文管理用于减少重复汇报和重复注入，让任务更容易续接。它不修改模型、账户限额或计费规则，不保证固定比例的 Token 节省，也不替代 Codex 的权限、安全及 Skills 读取规则。

## 1. 输出模式与作用范围

| 模式 | 适用行为 |
| --- | --- |
| 智能 `smart` | 默认模式。操作任务简短汇报，方案分析按需要展开。 |
| 精简 `concise` | 结果优先，减少客套、重复解释和逐步旁白。 |
| 详细 `detailed` | 对任务提供充分的解释、理由和必要示例。 |

三种模式都必须保留风险、失败、阻塞、必要进度和未验证项。用户明确要求完整交付时，不能截短代码、剧本、提示词、报告等正文。

配置按以下顺序覆盖：

`全局默认 → 项目设置 → 当前对话设置 → 用户本轮明确要求`

输出模式、启停状态、默认 Skills 和上下文预算可以分别继承。清除某一层的覆盖值，会恢复上层设置；默认 Skills 的空数组表示该层明确不选择技能，不等于继承。

项目身份来自后端确认的对话关联目录，界面不能通过提交任意文件路径改变作用范围。没有明确项目关联的对话仍可使用全局及对话设置，但不能写项目设置。

## 2. 默认 Skills 与收藏分离

- 收藏只是便于在列表中查找，不会自动成为对话默认技能。
- 默认 Skills 使用独立的结构化配置，不混入任务摘要或普通约定文字。
- 名称相同但来源不同的技能保留独立身份，不按名称合并。
- 默认选择是一种任务偏好，不代表已经读取或执行。仍须遵守宿主技能触发和完整读取规则。
- 钩子仅解析已安装技能的 ID、名称、标题及 `SKILL.md` 位置，不把技能正文一起注入。
- 未找到、扫描超时或当前不可用的选择会标记为不可用；不会默默换成同名技能。

没有默认技能，或本轮不需要追加上下文时，不启动技能目录扫描。需要解析时使用隔离进程，目录扫描有数量、深度、元数据大小和时间上限；当前元数据进程硬限为 1.4 秒。网络目录迟缓不应拖住对话。

## 3. 独立的任务上下文与事实来源

对话右上角、分享和面板工具旁的 **任务上下文** 打开独立右侧面板，不跳离对话。它绑定当前对话 ID，而不是全局设置或文件夹中的所有任务。切换对话会切换对应任务卡；同名任务也互相隔离。输出模式、默认 Skills 等偏好仍在设置中管理。

每个对话可保存以下字段：

| 字段 | 应填写的内容 |
| --- | --- |
| `goal` | 用户已明确的当前目标 |
| `progress` | 已实际完成或正在进行的阶段，不把计划写成结果 |
| `nextStep` | 下一步计划，不代表已经获得执行授权 |
| `agreements` | 已确认的约定与限制 |
| `references` | 任务卡、说明文档、输出文件等证据引用 |

首次打开面板会从当前对话的近期消息自动整理可编辑草稿，并展示来源与待核验提示。这里使用 **本地提取规则，不调用额外模型**，不是完整历史的 AI 语义总结：最多读取近期 2 MiB（受运行配置的更小上限约束），提取末 40 条可见消息，每条最多 6000 字符。不足以确认的内容留空；助手报告与建议保留待核验标记，不自动转成完成事实。

草稿不会自动保存或执行。已保存的非空字段优先保留；当前未保存编辑不会被后台整理覆盖。读取到新消息时可重新整理、检查来源并确认保存。历史原文留在原处，不会被任务卡替代。

任务上下文绑定对话 ID，而不是标题；同名对话不会共用摘要。保存带版本检查，遇到其他窗口更新会明确报告冲突，重新读取后再保存，不采用最后写入者静默覆盖。

所有引用数据都放入明确的非可信数据边界。即使摘要中出现命令或请求，也不能直接作为新增执行授权；文件引用也不会被自动展开读取。

### 保存并执行

先编辑并确认“下一步”，再预览将发送的完整内容。只有明确确认发送后，才保存当前任务卡并尝试向同一个原生对话输入框发送一次。确认绑定对话、任务卡版本和短期一次性令牌；切换目标、版本冲突或确认过期都会拒绝执行。

当前任务正在运行、输入框已有文字/附件、目标或原生发送按钮无法唯一识别时，不打断、不清空、不冒险发送。若仅安全填入而无法提交，界面提示手动发送。点击按钮不等于成功：只有在该对话的新用户消息中读回完全匹配的内容才显示已发送；结果不明时不自动重试。已发送也不代表任务完成，更不代表获得了额外的付费、发布、删除或授权许可。

## 4. 原生钩子的触发与预算

只注册两个事件：

- `SessionStart`：启动、恢复、清空或上下文压缩后，补入有界的输出偏好及任务参考。
- `UserPromptSubmit`：仅在当前有效策略或任务上下文版本发生变化时追加；未变化时不重复输出。

钩子按对话、会话代次和回合去重。**不注册 `Stop` 阻断器，不因为摘要维护强制续行，不自动调用模型或执行 Skills。** 错误按放行处理，原生对话继续运行。

任务参考预算默认 1400 个字符，可设置为 512–2400。整体追加内容硬上限为 3200 个 UTF-16 字符；安装配置同时设置有限的 `additionalContextLimit: 4096`。前者是本地文本上限，后者是宿主的近似 Token 上限，两者不是同一计量单位。超过本地预算时缩短参考内容，不破坏 JSON 和数据边界，不修改保存的原始记录。

## 5. 安装、审阅与信任

先完成 AIYOUCODEX 常规安装，并在实际保留的安装目录中执行以下命令。不要从即将删除的下载或临时目录注册脚本，因为钩子使用绝对路径。

仅预览，不写配置：

```sh
node scripts/setup-efficiency-hooks.mjs
```

确认后安装：

```sh
node scripts/setup-efficiency-hooks.mjs --apply
```

脚本默认读取活动 `CODEX_HOME` 下的 `hooks.json`；未设置时使用用户目录下的 `.codex/hooks.json`。它只合并 AIYOUCODEX 自己的处理器，保留其他钩子，并在修改现有文件前创建唯一备份。可通过 `--config` 指定要审阅的配置文件。

**写入配置不等于已启用。** 在原生 Codex CLI 输入 `/hooks`，审阅并信任名称为 `AIYOUCODEX: bounded output preferences` 的两个处理器。新定义或变更定义未被信任时，Codex 会跳过它们。项目级配置还需要项目层本身可信。随后恢复或开启实际对话，检查真实事件回执。

安装脚本不会修改信任数据库、`config.toml`、全局 `AGENTS.md`、当前会话或安全设置，也不会启用信任绕过。组织策略禁止用户钩子时，应尊重该策略，不尝试绕过。

Windows 的原生钩子默认由 `cmd.exe /C` 执行，与平时打开的 PowerShell 终端不是同一概念。只有宿主确实被配置为 PowerShell 命令执行器时，才使用：

```sh
node scripts/setup-efficiency-hooks.mjs --apply --windows-shell powershell
```

该选项会使用 PowerShell 的调用符和字面量参数引用；不要仅因终端是 PowerShell 就切换此项。

移除本模块的钩子、保留其他钩子及本地任务记录：

```sh
node scripts/setup-efficiency-hooks.mjs --remove --apply
```

## 6. 如何确认当前对话生效

应区分三种状态：

1. **已保存**：本地策略或摘要已写入，不代表宿主加载。
2. **等待真实执行**：可能尚未信任、尚未触发事件或宿主不支持；不能猜测具体原因。
3. **已收到当前策略匹配的回执**：真实钩子事件已经追加过该策略，最后发送的指纹与当前有效策略及摘要版本一致。

单看旧的时间戳、配置文件存在或一次手工测试不能宣称当前会话已加载。修改策略或摘要后，旧回执不会继续匹配。停用状态也不会显示为已生效。回执能证明本地钩子的执行与输出，不代替模型是否遵循每一项偏好的实际效果验证。

## 7. 本地数据与发布边界

策略、任务摘要和事件回执默认保存在 AIYOUCODEX 本地用户数据目录中的 `efficiency` 子目录，与运行程序分离。升级程序不需要重建这些记录。多个窗口或进程通过互斥锁、原子写入和乐观版本检查协调更新。

`AIYOUCODEX_EFFICIENCY_DIR` 仅用于明确指定其他本地存储位置或测试。不要将其设到准备提交或打包的源码目录。若有开发需求，使用已经被忽略的 `.aiyoucodex-private/` 目录，并在提交前运行发布边界检查。真实任务摘要、默认技能路径、钩子回执、备份文件和个人快捷入口配置不属于公开包。

公开包只包含通用实现、测试和本文档；不附带个人技能选择、账户凭据或私人入口配置。健康检查会检查输出与上下文模块必需文件是否齐全，但文件齐全不等于原生钩子已信任或实际执行。

## 8. 效果验证与兼容边界

建议用同类任务对照输入用量、缓存输入、输出用量、推理用量、完成率、返工次数和耗时。没有真实指标时显示不可用，不把账户剩余额度、回复字数或界面折叠当作 Token 节省量。现有长对话的历史也不会因为新增摘要而自动从模型上下文中删除。

当前实现依赖宿主原生钩子事件和信任机制。不同桌面及 CLI 版本可能不一致；遇到未知版本先验证事件是否实际触发，失败时保留原生对话。跨平台自动化测试不等于所有桌面版本的实机验收。

机制参考：[OpenAI Hooks 文档](https://learn.chatgpt.com/docs/hooks)、[原生命令执行器实现](https://github.com/openai/codex/blob/main/codex-rs/hooks/src/engine/command_runner.rs)。
