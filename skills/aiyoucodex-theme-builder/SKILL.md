# AIYOUcodex 主题构建

把参考图的主体、配色、材质与层次还原为可安装主题。主体融入聊天工作区，保持现有导航、项目、Dot / Claude、文件和上下文入口及发送行为。

开始前查看参考图和当前原生界面；定位当前 AIYOUCODEX 源码仓库，阅读 [主题契约](references/theme-contract.md)，以仓库中的 `lib/theme-package.mjs`、`lib/theme-build.mjs` 和两个现有皮肤为实际契约。不要用旧截图替代当前版本。

- 沿用用户指定风格。未指定动效时先制作静态主题；需要新视频素材时遵守当前任务的视频生成次数和指定供应商要求。复用现有媒体不算新增生成。
- 新主题必须有独立 `id` 和 `aiyoucodex.theme.<id>.v1` 设置键；修改旧主题才复用其身份。通过主题目录注册安装，保留其他皮肤、当前选择和个人媒体。
- 色卡覆盖 Codex、Dot、Claude、菜单、输入、工具结果、资产、竞技场、看板、设置等契约上下文。文字与底色分别控制；输入框内部及外层透明度分开，不能只给文字或祖先节点整体 opacity。
- 对话气泡须遵守 [主题契约中的气泡一致性标准](references/theme-contract.md#对话气泡一致性)：以用户指定 UI 和当前已发送气泡为基准，统一收发气泡的内边距、圆角、边框与阴影；角色只通过语义色和原生对齐区分。新增主题和模板都要在编译后的实际样式中验证，不能只检查色卡或截图。
- 实时预览、取消恢复、保存持久化、系统默认回退必须可用。动效只能观察事件，不触发发送、点击确认、工具执行或修改任务状态；装饰层 `pointer-events:none`。
- 用户要完整主题时，交付源文件、实际可安装包、色卡和原生截图；生成图只能作为主题素材或设计参考，不能冒充安装后的截图。

新皮肤可用 `scripts/scaffold-theme.mjs --repo REPO --id ID --name NAME --poster REFERENCE.png --output DIR` 建立静态模板。它复制现有静态适配器并生成独立身份，不会安装或发布。随后修改色卡、设计与样式；不要把模板复制当作完成还原。

用 `node scripts/install-theme.mjs --package DIR --dry-run` 检查身份、资源预算、语法和色卡，再按授权安装。检查实际原生界面：切换原有皮肤、输入草稿、发送按钮命中、权限入口、亮暗背景可读性、透明度、动效/静态回退、刷新后的恢复。确认界面后的截图和录制才是效果证据。打包时只包含主题源码与必要素材，不包含对话、个人媒体、账号、日志或 API 凭证。上传 GitHub 仅在当前用户明确要求时执行。
