# Codex 对话中的工作流与快捷编辑

全部需求理解、规划、澄清和执行汇报在当前 Codex 对话中完成。开始实际编辑时遵循父级 Skill：先检查安装状态，调用 `openchatcut_start_editing`，再读取当前工具目录和工程。右侧只提供真实素材、预览、时间线及编辑控件，不要求用户进入 OpenChatCut Agent 工作台、选择另一个聊天模型或重复输入需求。

下面将 OpenChatCut v0.2.16 的六类工作流和六项快速操作迁为 Codex 执行策略。上游入口只是提示模板，不是专用自动流水线。工具名称用于查找；参数必须读取当前返回的 schema，不能把本文件当作完整接口定义。所有操作通过插件 wrapper 绑定当前 `threadId` 和工程，遵守控制器授权与草稿审核规则。

## 六类工作流

| 用户目标 | 在当前对话中推进 | 完成依据 |
| --- | --- | --- |
| 口播净剪：去停顿、赘词并同步字幕 | 读取或转写素材，按词时间戳和内容标记删减范围；视频使用真实源范围 split/trim，音频可使用词流编辑；重排后同步字幕。 | 回读实际片段源范围、字幕与音轨，并检查切点声画同步。文字删除或时长缩短本身不能证明视频句内内容已剪除。 |
| 动态包装：标题、数据卡与转场动效 | 看帧并确定包装时刻，使用现有素材、允许的模板或文字/图形编辑能力完成放置与动画；需要代码图形时先检查当前工具与授权条件。 | 确认图形资产已放上时间线，检查尺寸、层级、进出场和关键帧。创建资产不等于已上轨。 |
| 长片拆条：提炼高光并重排为短视频 | 结合转写和画面理解选择有完整语义的高光源范围；用 `manage_timelines` 建立需要的版本，通过 `edit_item` 等实际剪辑工具复用源素材；分别处理构图、字幕与导出。 | 各版本具有独立时间线、明确源范围与可播放结果。`detect_scenes` 只检测画面切换，不能替代高光判断。 |
| 产品故事：围绕卖点组织脚本和镜头 | 从用户提供的产品事实与资产组织卖点、脚本和镜头；映射现有素材，完成通用剪辑、包装、字幕与音频。缺少影响结果的事实时在本对话澄清。 | 事实可追溯，镜头对应实际素材，成片中承诺与用户资料一致。不得补写未经提供或证实的产品功效。 |
| AI 影像：从概念生成镜头与声音 | 在 Codex 中规划故事、风格、镜头和连续性；依当前用户授权与媒体生成规则获取资产；将生成后的本地素材导入 OpenChatCut 组装。已有素材直接进入剪辑。 | 真实资产生成或导入成功，时间线实际应用，视听检查与输出路径可验证。对话模型不能代替未配置的画面、配音或音乐服务。 |
| 知识成片：把主题整理成清晰讲解 | 以用户材料组织章节、事实和旁白；根据现有或获准生成的旁白实际时长安排镜头、图形和字幕；逐章检查音画对应。 | 事实与材料一致，按真实音频时长完成同步，并检查字幕、图形和可播放成片。估算旁白时长不是同步完成证据。 |

## 快速操作

| 用户指令 | 工具组合与检查 |
| --- | --- |
| 删除填充词 / 去赘词 | `clean_script`、`delete_text` 可处理音频词流。视频须根据词时间戳使用 `split_item`、`edit_item` 等源范围剪切并核对声画；不要直接套用上游“删文字就是删视频”的承诺。 |
| 删除静音 / 去停顿 | `remove_silence` 依赖已可用的本地 VAD；词间空隙可结合 `clean_script`、`edit_gap`。检查 `edited`、跳过原因及实际时间线；开关关闭时返回 `ok: true, edited: []` 是未编辑。同轨 ripple 不会自动移动其他轨，需检查字幕、包装与音频同步。非 1 倍速、词流编辑或 animated zoom 片段可能被跳过。 |
| 跳切 | 根据内容与源范围组合 `split_item`、`edit_item`、删除及重排；没有可依赖的专用 `jump_cut` endpoint。检查切点、口型与音频连续性。 |
| 生成字幕 / 加字幕 | 先检查已有转写；需要时调用 `transcribe_track`，再通过 `edit_captions`、`read_captions` 完成字幕样式和同步。启用字幕不会自动转写，`display_text` 只改变显示文字；双语先创建实际翻译 variant。 |
| 响度标准化 | `normalize_loudness` 默认目标为 −14 LUFS，仅处理 `kind=audio` 的片段；视频原声不直接处理。检查 `normalized` 与 `skipped` 并回读音量；空结果不能称为已标准化。该操作写音量 gain，不等于降噪、压缩或重写媒体文件。 |
| 横转竖 | 设置 `set_aspect_ratio` 为 9:16，再逐片段检查并使用 `auto_reframe` 或手调构图。自动构图依赖真实浏览器视频像素，并会清除旧 reframe keyframes；改比例后仍需检查主体、字幕安全区和包装位置。 |

## 实现和资源边界

- 视频删词：当前 v0.2.16 的 Script 编辑会更新删词元数据与时长，但视频仍按连续 `srcInFrame` 渲染；词流播放窗口仅对音频生效。用真实源范围重建视频剪辑并检查结果。
- 多版本复用：当前 `apply_script` 拒绝新增、重放和重复占位符，不能靠复制 `[sN]` 实现片段复用。使用独立时间线和真实源素材范围。
- 动效代码：`create_motion_graphic_from_code` 是本地代码图形能力，但当前控制器不将执行外部代码纳入自动剪辑授权。遵守原生精确参数确认及现有授权规则；不得通过别名、直连上游或修改控制器绕过限制。
- 转写：优先沿用已有转写。显式 `provider: local` 仍需本地 ASR 模型可用；云端转写遵循对应授权和供应商规则。隐藏 Agent 聊天不影响这些资源要求。
- 生成：从当前用户指令和有效全局规则读取指定通道、禁用供应商与累计次数限制，不把个人通道偏好写入共享插件。达到用户设定的直接提交上限后，每次新增生成须按规则取得明确确认。未确认 OpenChatCut 支持指定通道时，先通过获准通道生成本地资产，再导入继续剪辑，不把聊天 `baseUrl` 当作视频接口适配。
- 结果：每次编辑检查工具返回、审核/应用状态及真实工程回读；`ok: true`、空数组、待确认卡或未应用草稿均不能替代实际完成。导出使用真实目录中的 `submit_render_job` 和 `track_export`，保留 `renderId` 并验证落盘文件可播放。
